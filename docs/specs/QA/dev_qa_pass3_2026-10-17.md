### 2.7. Field Diagnostics & Accounting Invariants Resolution
- **Issue A: Probe Timeout When Onboarding Community Key (`AIzaSyD1kh...`)**
  - *Symptom:* Adding a Google community key returned HTTP 503 `"The provider is not answering right now. Please retry in a minute."`
  - *Root Cause:* `PROOF_MODEL_GOOGLE` in `src/ingress/probe.ts` was hardcoded to `gemini-3.5-flash-lite`. Upstream preview queuing delays reached >41s, breaching the 8-second probe timeout.
  - *Resolution:* Replaced proof model with `gemini-3.5-flash` (1.8s - 2.1s latency) and automated fallback to `gemini-3.6-flash`. Deployed and verified.
- **Issue B: Active Community Keys Displayed "4 / 7" Instead of "4 / 4"**
  - *Symptom:* UI displayed `Active Community Keys 4 / 7` for Account A who only owned 4 community keys (and 1 private healthy key).
  - *Root Cause:* `src/worker/pool_routes.ts` did not filter `status != 'REVOKED'`, counting 2 dead legacy keys. In addition, `PoolView.svelte` displayed active community keys divided by total keys of all types.
  - *Resolution:* Added `AND UPPER(status) != 'REVOKED'`, returned `community_total_keys`, and updated `PoolView.svelte` to display `{community_active_keys} / {community_total_keys}` (`4 / 4`). Deployed and verified.
- **Issue C: "Requests Served for Community" Displayed 5 vs 2 Completed Requests**
  - *Symptom:* `cost_ledger` recorded 2 successful requests (`f9ec99db` and `98256e35`), but UI displayed 5 requests served.
  - *Root Cause:* In `PoolCoordinatorDO`, `dispatches_communal` increments on every `settle()` where `borrowed: true`. The 3 additional counts represented earlier lease dispatch attempts that encountered upstream quota or probe errors before completing.
- **Issue D: Identical 7 CU Charged for Both "Ping" and "Quantum Entanglement"**
  - *Symptom:* Both minimal ping and full paragraph requests cost exactly 7 CU.
  - *Root Cause:* `gemini-3.5-flash-lite` pricing is `{ cuBase: 5n, cuInPer1k: 1n, cuCachedPer1k: 0n, cuOutPer1k: 2n }`. Prompt tokens for both requests were ≤ 10, and completion tokens ≤ 16. Integer ceiling division `ceilDiv(tokens, 1000)` rounded both up to 1 CU in + 1 CU out: `5 + 1 + 1 = 7 CU` (the mathematical integer floor under zero-float GEMINI.md Invariant 3).
- **Issue E: Project RPM Sub-cap Enforces Legacy Tier Limits**
  - *Symptom:* Setting project RPM sub-cap > 10 returns `SUB_CAP_ABOVE_TIER`.
  - *Root Cause:* `src/worker/router/dashboard/project_routes.ts` validates sub-caps against `calculateProjectQuota(owner.tier)`. OAuth accounts default to `builder` tier in D1 (`users.tier = 'builder'`), where `TIER_LIMITS_MAP.builder.rpmLimit = 10`.
