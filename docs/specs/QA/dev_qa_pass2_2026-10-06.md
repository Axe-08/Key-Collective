    1. *Cross-Tenant State Leakage (Fixed):*
       - **Symptom:** Admin account (`bansalakshit2004`) saw keys created by another account (`Axe-08`) under "My Provider Keys", but actions (`/test`, `/pool-mode`) returned `404 Not Found`.
       - **Root Cause:** `get_keys.ts` elevated any user with D1 `role === 'admin'` to `isGlobal = true`, running unscoped queries and forcing `is_owner: true`. Meanwhile, `ops.ts` correctly scoped operations to the user's `tenantId`, resulting in 404s.

       - **Symptom:** Newly generated keys from Google AI Studio use the new Authorization key format (`AQ...`, 54 chars) rather than legacy standard keys (`AIza...`, 39 chars). Submission was rejected with `400 Bad Request` ("Key format does not match the provider"), and `forceErrorGcpProbe` failed with 401 on non-Gemini endpoints.

       - **Fix:** Updated regex in `post_key.ts` to accept `AIza` or `AQ.`, bypassed `forceErrorGcpProbe` for `AQ.` keys (falling back to unprobed project state like Groq), updated UpstreamClient keyResolver bypass and error sanitizers, and updated UI modal warning guards. Verified with `make gate` (commit `9901bb5`).
